# TASTE-skills 选择性迁移设计

日期：2026-08-05

## 目标

在不改变 TASTE 现有 Find/Read 主流程语义的前提下，吸收更新版
TASTE-skills 中对当前仓库确有价值的两类能力：

1. Read 缓存同时绑定全文、题录摘要和当前质量契约，避免内容变化后复用陈旧精读结果。
2. 为缺少稳定全文入口的论文补充结构化 OpenAIRE/HAL 候选，但仍由 Read 现有身份校验决定是否接受全文。

本修改保留 Find 的“部分结果可用但明确标记受限”语义，不因单条记录缺失而让整个来源失败。

## 已确认的迁移边界

### 纳入

- Read 缓存指纹增加来源英文摘要和已接受的固定中文摘要。
- Read 缓存恢复时要求当前质量策略/内容契约一致。
- 旧缓存缺少新字段时只让精读文本失效；已验证的 PDF/全文缓存继续复用。
- 以标准题录字段传递 OpenAIRE 仓储候选 URL。
- Read 增加 HAL 精确检索和 OpenAIRE 仓储页面候选处理，并继续执行现有 PDF 身份验证。
- 在现有集中测试目录补充针对上述边界的回归测试。

### 不纳入

- 不替换现有 14 个会议和通用来源适配器。
- 不引入“一条记录不完整就让整个来源失败”的严格完整性规则。
- 不引入 arXiv/bioRxiv 按日全量分片缓存。
- 不按会议新增重复脚本。
- 不改变当前同服务/同主机的并发与冷却策略。
- 不修改 Claude 提示词、Read Markdown 格式、评分与排名、任务栏或 Web 界面。
- 不新增 `modules/reading/tests`。

## 设计一：Read 缓存契约

### 指纹

单篇 Read 缓存清单继续保存现有全文和 PDF 指纹，并新增：

- `source_abstract_sha256`：Read 实际接收的来源英文摘要的规范化文本哈希。
- `fixed_abstract_zh_sha256`：经过现有清洗和接受逻辑后、要求原样使用的中文摘要哈希；不存在时使用稳定的空值哈希语义。

组合内容版本由以上摘要指纹与现有 `full_text_sha256`、`pdf_sha256` 共同决定。哈希只用于缓存身份，不进入模型提示词或最终产物。

### 恢复规则

恢复 `read.md` 缓存必须同时满足：

1. 现有论文身份、全文/PDF 指纹校验通过；
2. 两个摘要指纹与当前输入一致；
3. 缓存记录的 Read 内容质量策略版本与当前版本完全一致；
4. 现有 Markdown 内容质量门禁仍然通过。

任一新增条件不满足时，只视为精读文本缓存未命中，重新生成该篇 Read 内容；不得删除或重新下载已经通过身份验证的全文/PDF。

旧缓存如果没有摘要指纹或质量策略版本，不再回填为“等价的新缓存”，但其中可独立验证的全文/PDF 仍按原有逻辑复用。这避免一次升级引发无谓下载，也避免把语义陈旧的精读结果继续当成合格缓存。

## 设计二：OpenAIRE/HAL 候选

### 组件边界

Find 只负责题录发现与结构化元数据补全；Read 只负责全文候选发现、下载和身份验证。两者不互相导入代码：

```text
Find 题录补全 -> paper 标准字段 -> Read 候选归一化 -> 现有全文身份校验
```

Find 可在已有 DOI/标题/作者证据足够时写入 `openaire_repository_urls`。Read 把它作为普通候选字段消费，而不了解 Find 使用了哪个内部适配器。

HAL 的全文发现由 Read 自己的 acquisition 层负责，避免依赖 Find 是否曾经运行 HAL 摘要补全。

### OpenAIRE 接受条件

- 优先用规范化 DOI 精确匹配。
- 无 DOI 时，必须标题规范化后精确一致，并有作者证据相符。
- 只保留 OpenAIRE 明确声明的仓储落地页或直接 PDF URL。
- 仓储落地页只能用于提取页面明确声明的 PDF 链接，不能把 HTML 当全文。
- API 失败、429、字段缺失或身份不足时不阻塞论文，继续现有其他渠道。

### HAL 接受条件

- 使用精确标题检索，并尽可能同时校验 DOI 或作者。
- DOI 冲突或作者证据明显不一致时拒绝该候选。
- 只接收 HAL 返回的全文文件或明确的 HAL 记录落地页。
- 下载后的内容仍必须通过 Read 现有 PDF 格式与论文身份验证。

### 路由位置

OpenAIRE/HAL 属于结构化仓储候选：排在会议/出版方/OpenReview 等官方入口之后，排在宽泛 Web 搜索之前。它们失败时不改变其他渠道的次序和可用性。

## 错误与状态语义

- Find 的来源完整性状态保持现状；新增补全渠道只能增加元数据，不得把部分成功清零。
- OpenAIRE/HAL 的瞬时失败记为该候选不可用，不把论文误报为“PDF 不可读”。
- 只有所有既有和新增候选都耗尽后，才沿用当前 Read 的全文不可用状态。
- 缓存契约不匹配是缓存未命中，不是论文抓取失败。

## 验证

测试只加入仓库现有集中测试体系，覆盖：

1. 来源英文摘要变化会使 Read 文本缓存失效，但不使全文缓存失效。
2. 固定中文摘要变化产生相同效果。
3. 质量策略版本不一致时不恢复 Read 文本。
4. 缺少新增字段的旧缓存不能被静默升级为合格 Read 缓存。
5. OpenAIRE DOI 精确匹配和标题/作者匹配；身份冲突不产生候选。
6. HAL 精确标题匹配、身份冲突处理和候选顺序。
7. OpenAIRE/HAL 失败不会阻断其他现有来源。
8. 运行与 Find、Read、缓存相关的既有回归测试，确认产物和并发语义未变化。

## 预期结果

修改后，TASTE 保留自己更广的来源覆盖、渐进式 Find 状态和严格全文身份校验，同时获得更新版 TASTE-skills 最有价值且适合当前架构的缓存语义与结构化仓储候选。新增能力通过数据契约连接，不形成 Find 与 Read 的代码耦合。
